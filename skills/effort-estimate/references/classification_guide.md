# 分類・係数判定ガイド

判断に迷ったときは、**根拠を説明しやすいほう**を選ぶ。どちらを選んだかと理由は、タスクの `reason` に書く。

## サイズ（S / M / L）の判定基準

| サイズ | 目安 |
|---|---|
| S | 既存の実装パターンをほぼそのまま踏襲できる。変更は1〜2ファイル程度。設計判断がほとんどない |
| M | 既存パターンを参考にしつつ、新しいロジックや分岐が入る。変更は3〜5ファイル程度 |
| L | 新しい設計判断が必要、または複雑な分岐・状態管理がある。変更は6ファイル以上 |

L を超えると判断した作業は、意味のある単位（例：エンドポイント単位、画面単位）に分割する。

### 作業種別ごとの補足

- `api_endpoint`：1エンドポイント＝1タスク。複数あれば個別に計上する。リクエストクラスでのバリデーションは、量が多い場合のみ `validation` として分ける。
- `investigation`：改修箇所が1機能に閉じていれば S、複数機能・複数レイヤーにまたがれば M、影響範囲が読み切れず広範囲を確認する必要があれば L。
- `client_qa`：依頼の時点で仕様が明確な場合は計上しない。確認したい点は「先方への確認事項」に書くだけでよい。計上するのは、回答がないと作業を始められない、または複数回のやり取りが見込まれる場合に限る。計上する場合のサイズは、確認事項が1〜2点なら S、複数回のやり取りが想定されるなら M 以上。
- `automated_test`：既存のテスト構成にケースを追加するだけなら S、テストのデータ準備やモックが必要なら M、テスト基盤から整える必要があれば L。既存テストがないリポジトリでは、その旨を前提条件に書き、作成するかどうかを判断する。
- `regression_test`：変更した処理を呼び出している箇所が少なければ S、複数画面・複数機能から呼ばれていれば M 以上。
- `review_fix`：実装タスクの合計規模に合わせる。実装が小規模なら S、中規模なら M、大規模なら L。
- `design`：既存の実装パターンに沿えば作り方が決まる場合（1コマンド・1画面の追加など）は計上せず、`investigation` または実装タスクに含める。計上するのは、方式の比較・選定や設計書の作成が必要な場合に限る。
- `doc_update` / 関係者との質疑：案件の規模が小さい場合は、`release` や `review_fix` に含めて別タスクにしない。

## 補正係数の判定基準

### uncertainty（仕様の不確実性）

- `low`：仕様が明確で、解釈の余地がない
- `mid`：細部が未確定だが、妥当な前提で進められる（前提条件に書く）
- `high`：仕様の大部分が未確定、または先方の回答次第で作り方が変わる

### complexity（既存コードの複雑さ）

- `low`：構成が素直で、該当箇所が読みやすい
- `mid`：処理が複数クラスに分散している、命名や構成が一貫していないなど、読み解きに時間がかかる
- `high`：巨大なクラスやメソッド、テストがない、副作用が読み切れないなど、変更のリスクが高い

### unfamiliarity（未経験の技術・領域）

- `none`：チームが普段扱っている技術・領域
- `partial`：一部に未経験のライブラリ・仕組みを含む
- `new`：主要部分が未経験の技術・領域（例：初めて扱う外部サービス）

## 案件全体のリスク（project_risk）

バッファ率の決定に使う。タスクごとの係数では拾えない「想定外の作業」に備えるもの。バッファの時間は実作業見込みの小計から算出し、対外工数にも同じ時間を保険として載せる。

- `low`：小規模で、影響範囲がはっきりしている
- `mid`：通常の改修。影響範囲は把握できているが、多少の想定外はありうる
- `high`：影響範囲が広い、本番データに影響する、リリース手順が複雑など

タスクの係数（uncertainty / complexity）にすでに入れたリスクは、project_risk の理由に使わない。project_risk は、タスクに分解しきれない想定外の作業に備えるものとして判定する。例：「本番データを物理削除する」ことを、削除処理や検証のタスクの係数で見込んだなら、それだけを理由に high にしない。

## custom（どの種別にも当てはまらない作業）

三点見積もり（`optimistic` / `likely` / `pessimistic`、AI支援ありの時間）を付ける。計算は PERT 式 `(楽観 + 4×標準 + 悲観) / 6` で行い、対外工数は `custom_traditional_ratio` を掛けて算出する。custom にも補正係数は適用される。
